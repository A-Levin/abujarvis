# Абу-Джарвис

Менеджер для **долгоживущих** табов Claude Code.

У тебя tmux-сессия с десятком инстансов Claude Code — по одному на проект, по одному на область
жизни. Абу-Джарвис видит, кто чем занят, раздаёт задачи и показывает доску.

[In English](README.md)

```
$ abujarvis board
WORKING (2)
    2  api                  ● Починить флапающий тест оплаты
       next: прогнать сьют, оформить PR | queued: 1
    5  docs                 ● Переписать гайд по онбордингу

BLOCKED (1)
    8  billing                Ждёт ключ от стейджинга

NO TASK (12)
    1  notes                  ~/notes
```

## Зачем он, если есть готовые

Почти все инструменты в этой нише (claude-squad, vibe-kanban, kanban-code…) построены на модели
**задача → новый git worktree → свежий агент → PR**. Это отличная модель для выкатывания фич, и
если она тебе подходит — бери их, они зрелее.

Абу-Джарвис про другую форму: табы, которые **уже существуют и живут дольше любой задачи**.
Часть из них — вообще не код: заметки, учёба, дневник. Их не создают под задачу, в них просто
работают.

Отсюда два решения, и в них весь смысл:

- **Он никогда не перебивает таб.** Задачи кладутся в очередь. Таб берёт задачу, только когда
  доделал своё и собирается остановиться. (Другие инструменты доставляют работу через
  `tmux send-keys` — то есть печатают агенту прямо посреди мысли.)
- **Он никогда не угадывает.** Состояние берётся из `claude agents --json` — официального
  интерфейса, а не из парсинга ANSI-вывода терминала.

## Установка

Нужны Python 3.8+, tmux и Claude Code.

```bash
git clone https://github.com/A-Levin/abujarvis
cd abujarvis
./install.sh
```

Ставит симлинки CLI в `~/.local/bin` (`abujarvis` и короткий `aj`), кладёт роль менеджера в
`~/.abujarvis/CLAUDE.md` и регистрирует четыре хука в `~/.claude/settings.json` (рядом пишется
бэкап). Существующие хуки не трогаются.

## Использование

```bash
abujarvis ls                        # все табы: окно, статус, проект
abujarvis board                     # канбан по стадиям
abujarvis jump api                  # перейти в таб
abujarvis assign api "подтяни мастер в открытый PR"
abujarvis chat                      # поговорить с менеджером
```

`abujarvis chat` — это просто Claude Code с ролью менеджера: он вызывает `abujarvis ls` и
отвечает по тому, что увидел, поэтому не может выдумать состояние сессии.

Изнутри таба агент рассказывает о себе сам (ему это велят хуки, тебе делать ничего не надо):

```bash
abujarvis set --goal "Починить флапающий тест" --stage doing --next "прогнать сьют"
```

## Как устроено

| | |
|---|---|
| **Кто запущен** | `claude agents --json` → pid, sessionId, cwd, имя, статус |
| **В каком окне tmux** | подъём по цепочке PPid в `/proc` от pid до `pane_pid` |
| **Чем занят таб** | `~/.abujarvis/state/<sessionId>.json` — хуки пишут факты, агент пишет смысл |
| **Раздача задач** | `~/.abujarvis/inbox/<sessionId>.jsonl`, разгребается `Stop`-хуком |

Идентификатор — `sessionId`, а не pid: pid умирает при перезапуске таба, sessionId переживает.

### Почему очередь, а не «напечатать в таб»

Вписать промпт в **живой** интерактивный процесс Claude Code программно **нельзя** —
`claude --resume` порождает *новый*. Поэтому единственный корректный канал — дать табу самому
прийти за работой:

1. `abujarvis assign` дописывает задачу в inbox таба (под `flock`).
2. Таб доделывает своё, собирается остановиться — срабатывает `Stop`-хук.
3. Хук достаёт задачу и возвращает `{"decision": "block", "reason": "<задача>"}`.
4. Агент продолжает работу — уже над этой задачей.

Защита от петли: если пришло `stop_hook_active`, хук выходит сразу — и задача **остаётся
в очереди**, а не съедается.

### Карточки

Хуки пишут то, что можно измерить. Агент пишет то, что знает только он.

```json
{
  "cwd": "…", "branch": "fix-checkout", "dirty_files": 4,  // хуки
  "last_prompt": "почини флапающий тест",                  // хук
  "goal": "Починить флапающий тест оплаты",                // агент
  "stage": "review", "next": "прогнать сьют, оформить PR"  // агент
}
```

Одной инструкции агенту не хватило бы: он рано или поздно забудет, и доска начнёт молча врать.
Доска, которой нельзя верить, хуже, чем никакой.

## Что он пишет на диск

Хуки регистрируются **глобально**, то есть срабатывают в каждой сессии Claude Code, а не только
в табах управляемой tmux-сессии. На каждую сессию Абу-Джарвис пишет одну карточку в
`~/.abujarvis/state/<sessionId>.json` (права `0600`): cwd, ветка, число грязных файлов и то, что
агент рассказал о себе сам.

Промпты по умолчанию **не логируются**. Если хочешь, чтобы первые 200 символов каждого промпта
тоже попадали в карточку — `ABUJARVIS_LOG_PROMPTS=1`.

Задачи и их история — в `~/.abujarvis/inbox/` и `~/.abujarvis/done/`.

Никуда ничего не отправляется, всё лежит локальными файлами.

## Модель доверия

Inbox — обычный файл. Любой процесс от твоего пользователя может положить задачу в очередь
таба — в том числе другой агент Claude Code. Задача отдаётся агенту как *пользовательский ввод*,
а не как системный приказ: агент сохраняет своё суждение и права и может отказаться. Но если таб
запущен с `--dangerously-skip-permissions`, относись к его inbox как к доверенному входу — потому
что это он и есть.

## Рубильник

```bash
touch ~/.abujarvis/OFF     # все хуки мгновенно становятся no-op
```

Хуки вмешиваются в жизненный цикл каждого таба, в котором ты работаешь, — поэтому это важно.
`hook.py` целиком обёрнут в `try/except → exit 0`: битый JSON, пустой stdin, отсутствие
session id, не-git каталог — везде тихий выход, а не поломка таба, в котором ты печатаешь.

Задачи из очередей при OFF не теряются, они просто не раздаются.

Если репозиторий переехал или удалён, хуки становятся no-op, а не блокируют табы: в
зарегистрированной команде стоит проверка, что `hook.py` на месте. Чтобы снести Абу-Джарвиса
по-человечески:

```bash
./uninstall.sh     # снимает хуки и CLI; состояние не трогает
```

Одна оговорка: задача забирается из очереди *до* того, как агент за неё возьмётся. Если сессия
умрёт ровно в этот момент, задача исчезнет из очереди невыполненной.

## Состояние

Работает: реестр табов, карточки, канбан в терминале, очередь задач, менеджер-собеседник.

Не сделано: TUI/веб-доска и роль «полного оркестратора» (создавать и убивать табы, заводить
worktree, перезапускать зависшие) — она трогает живую сессию, поэтому ждёт.

## Настройки

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `ABUJARVIS_SESSION` | `dev` | какой tmux-сессией управляем |
| `ABUJARVIS_HOME` | `~/.abujarvis` | состояние, очереди, роль менеджера |
